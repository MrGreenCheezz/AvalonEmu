# Моды клиента (BepInEx 6, только для локального сервера)

Английская версия: [README.md](README.md). Это необязательные плагины клиента для работы с ЭТИМ локальным сервером.
**Никогда не запускайте клиент с BepInEx на официальных серверах.** Использование — на вашу ответственность;
игровых файлов здесь нет, античит не затрагивается и не обходится.

Собрано для клиента **1.32.030.345319** и BepInEx 6 bleeding edge **#788**
(`BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.788+5b766a3.zip` с `builds.bepinex.dev`, SHA-256
`f4cc496bd098a0df4164b81e3737297707f13a47c2478dba2f60eefab784817a`).

## Установка

```powershell
powershell -ExecutionPolicy Bypass -File tools\install-client-mods.ps1 -GameDir "C:\Games\Albion\game"
```

`-GameDir` — папка клиента, где лежит `Albion-Online.exe`. Скрипт проверяет папку, скачивает BepInEx с официального
адреса, сверяет SHA-256, распаковывает **без перезаписи** существующих файлов и кладёт `client-mods\dist\*.dll` в
`BepInEx\plugins`. В корне клиента появляются `winhttp.dll` (загрузчик Doorstop), `doorstop_config.ini`,
`.doorstop_version`, `changelog.txt`, папки `BepInEx\` и `dotnet\`. Ни один существующий файл не меняется.

Если файлы папки клиента — жёсткие ссылки NTFS на другую установку (копия, сделанная жёсткими ссылками), добавлять
новые файлы безопасно, но **никогда не правьте существующие файлы на месте** — изменится и оригинал. Установщик только
добавляет файлы.

**Отключить:** переименовать или удалить `<папка игры>\winhttp.dll` — клиент запустится как обычно.
**Удалить совсем:** `tools\uninstall-client-mods.ps1 -GameDir "..."`.

При первом запуске BepInEx скачает базовые библиотеки Unity с `https://unity.bepinex.dev/libraries/6000.3.12.zip`
и сгенерирует обёртки (`BepInEx\interop`) — это может занять несколько минут. Журнал: `<папка игры>\BepInEx\LogOutput.log`.

**Сборка из исходников:** после одного запуска игры с BepInEx — `tools\build-client-mods.ps1 -GameDir "..."`
(или `dotnet build -c Release -p:GameDir="..."` в папке мода).

## HelloMod

Проверка совместимости (только исходник): пишет в журнал, что плагин загружен, версию рантайма и число
сгенерированных сборок. Первый запуск: Cpp2IL читает метаданные v39 (~40 с), Il2CppInterop генерирует ~130 сборок
в `BepInEx\interop` (~2 мин).

## CameraMod (камера: дальний зум, свободный поворот, вид от третьего и первого лица)

Исходники: `CameraMod\` (заметки по камере игры — `CameraMod\NOTES.md`). Сборка: `tools\build-client-mods.ps1` (готовая DLL — в `dist\`).

Мод перехватывает `ActorCameraController.LateUpdate` (камера, следующая за игроком) через Harmony и только
дорабатывает уже посчитанную игрой позицию камеры. Пока ничего не нажато — камера как в обычной игре.

**Управление (по умолчанию):**
- Колесо мыши — как в игре; когда игровой зум упёрся в предел, колесо продолжает отдалять (до `MaxDistanceMultiplier`
  × игровое максимальное расстояние, по умолчанию ×2) или приближать (до `MinDistanceMultiplier` × минимальное, ×0.5), плавно.
- Средняя кнопка мыши (или Alt + правая кнопка) + движение мыши — вращение камеры вокруг персонажа и наклон
  (ограничен `MinPitch`…`MaxPitch`, 5…85°).
- `Home` — сброс поворота и дополнительного зума к обычному виду.
- `F8` — эксперимент «от первого лица»: камера в голове персонажа, обзор мышью при зажатой правой кнопке
  (или всегда, если `AlwaysMouseLook = true`), модель игрока скрыта, ближняя плоскость отсечения 0.05,
  дальняя — до 1500 (с v7 по умолчанию пресет Performance: 600 и до конца тумана), `layerCullDistances` сброшены (с v7 только при
  `Preset = Custom`). Повторное `F8` возвращает всё как было (рендеры, плоскости отсечения, положение камеры).

**Первое лицо v2 (F8):**
- Туман: `FirstPersonView.FirstPersonFog` = `Off` / `Reduced` (по умолчанию, дальность тумана × `FogDistanceMultiplier` = 4) /
  `Default`; `FirstPersonFarClip` (1500), `LodBias` (2, 0 = не трогать). При выходе всё возвращается. Мобы и игроки дальше
  ~40 м не приходят с сервера — это `Visibility` в `config\world.jsonc` (EnterCells/LeaveCells).
- Своё тело: `FirstPerson.ShowBody` = `None` (скрыть всё) / `BodyOnly` (скрыть только голову/волосы/шлем) / `All`;
  `HideMode` = `ShadowsOnly` (тень остаётся) / `Disable`; `DeepScan`; `HeadForwardOffset` (0.15), `HeadUpOffset` (0.25).
  Скрытие обновляется постоянно, поэтому смена экипировки подхватывается. Список мешей персонажа пишется в журнал при первом входе.
- Мышь: `LookMode` = `HoldRight` (обзор при зажатой правой кнопке) / `Toggle` / `Always`; `MouseLockKey` (CapsLock)
  включает и выключает обзор мышью. Во время обзора курсор спрятан и прижат к центру окна, на экране прицел (`Crosshair`,
  `CrosshairSize`). Поэтому клик, наведение на цель и прицеливание умений игры идут через прицел.
- Сыро: умения, нацеленные выше горизонта, игра направляет в точку персонажа; ЛКМ по земле через прицел = идти туда.

**Первое лицо v3 (F8):**
- Ходьба на **WASD** (секция `FirstPersonMove`, `MoveForward/MoveBack/MoveLeft/MoveRight` = W/S/A/D, включено по умолчанию):
  направление от взгляда камеры. Пока включено первое лицо, игровые горячие клавиши на W/A/S/D игнорируются
  (`BlockGameMoveKeys`; перехвачен общий диспетчер горячих клавиш игры), вне первого лица всё как обычно.
- Умения с W и D (и A) в первом лице — через `FpSpellKeys` (пары `Откуда=ИгроваяКлавиша`), по умолчанию
  `Alpha3=W, Alpha4=D, Mouse3=W, Mouse4=D, Z=A`: **3** или задняя боковая кнопка мыши = умение W, **4** или передняя
  боковая = умение D (шлем), **Z** = A. Q, E, R, F, 1, 2 работают как обычно; Alt + клавиша = каст на себя, как в игре.
- `MoveMethod` = `Auto` (по умолчанию: игровой ввод направления `HandleInputActionsMove`; если персонаж за 0.5 с
  не сдвинулся — переключается на `ClickMove`) / `InputAction` / `ClickMove` (точка в 3 м впереди, как клик по земле,
  `DoMoveTriggered`). `IntervalMs` 100, `LookAheadMeters` 3. Ввод в чат не двигает персонажа.
- Эффекты у лица: секция `FirstPersonEffects`, `FpHideEffects` = `NearCamera` (по умолчанию: скрыть частицы/шлейфы/линии
  на своём персонаже у головы/шеи или ближе `FpEffectRadius` = 0.6 м к камере, а также любые частицы в сцене, касающиеся
  камеры) / `AllOnSelf` (все эффекты на своём персонаже) / `Off`. Эффекты на других персонажах и мобах видны.
  `HideOwnNameplate` (true) — скрыть своё имя/полоску здоровья над головой.
- Небо: секция `FirstPersonSky`, `SkyMode` = `Auto` (по умолчанию: Unity `Skybox/Procedural`, если шейдер есть в сборке,
  иначе купол) / `Procedural` / `Dome` / `Off`. Купол — градиент от цвета тумана у горизонта (`SkyHorizonFromFog`, иначе
  `SkyHorizonColor`) к `SkyZenithColor` (#4A80C8), свечение у солнца `SunGlow`, облака `Clouds` (`CloudCover` 0.5,
  `CloudSpeed` 1), `DomeRadius` 1000. При выходе из первого лица всё возвращается.

**Первое лицо v4 (F8) — «играбельно»:**
- Вход по `F8`: взгляд туда, куда смотрит персонаж; повторное `F8` — обратно к обычному виду сверху (FOV, отсечение, тело,
  туман, небо, эффекты восстанавливаются).
- **Мышь как в шутере** (секция `FirstPersonControls`, `MouseLook = Always` по умолчанию): курсор спрятан и держится на прицеле,
  мышь поворачивает взгляд. Освободить курсор: удерживать **левый Alt** (`FreeCursorKey`) или переключить **CapsLock**
  (`MouseLockKey`). Курсор освобождается сам, пока открыто окно игры (инвентарь, добыча, меню, ...) или ввод в чат
  (`AutoFreeCursor`), и снова захватывается, когда окно закрыто. `Sensitivity` (секция `FirstPerson`, 0.15),
  `InvertY`, `PitchUpLimit` (80) / `PitchDownLimit` (85). Старые режимы: `MouseLook = HoldRight` / `Toggle`.
- **ЛКМ** — атака юнита под прицелом / использование (сундук, добыча, NPC): к игровому клику добавляются флаги «атака + взаимодействие»
  (`LeftClickAttack`); клик по земле больше не ведёт персонажа (`ClickMove = false`, ходьба — WASD).
- **ПКМ** — `RightMouse` = `Game` (как в игре) / `None` (ничего) / `Hotkey` (как игровая клавиша `RightMouseHotkey`, по умолчанию W).
- **G** (`InteractKey`) — взаимодействие с тем, что под прицелом (то же действие игры, что клик «использовать»).
- Умения: Q E R F 1 2 как обычно; `FpSpellKeys` (3 / боковая 4 = W, 4 / боковая 5 = D, Z = A); Alt + клавиша — на себя.
  Наземные умения бьют в точку под прицелом; если прицел у горизонта или выше, точка ставится на землю в `AimMaxDistance`
  (15 м) впереди (маленькая точка на экране показывает, куда смотрит курсор игры). 0 — выключить.
- **WASD**: запрос движения отправляется сразу при смене клавиш и при повороте взгляда > 3°, иначе раз в `IntervalMs`;
  отпускание — мгновенная остановка. Своего «поворота лицом» в игре нет: персонаж поворачивается по ходу движения и к цели умения.
- **F1** (`HintKey`) — панель подсказок по клавишам (`ShowHintOnEnter`). Внизу слева строка: режим, курсор (захвачен / свободен и почему),
  способ ходьбы.
- **Плавность** (секция `FirstPersonCamera`): `PositionSmoothingMs` (70) — камера догоняет позицию пружиной без рывков от
  поправок сервера и анимации; `HeadBob` (0.15; 0 — ровная высота глаз, 1 — как раньше, прямо на кости головы);
  `EyeHeightAdaptSec` (0.4) — как быстро высота глаз следует за посадкой на маунта и т. п.; `LookSmoothingMs` (0 — мышь без задержки);
  `FieldOfView` (75; 0 — как в игре).
- **Эффекты косметики** (секция `FirstPersonEffects`): эффекты vanity-предметов, экипировки и баффов — это отдельные объекты
  (`Vfx`, `ConstrainableObject`), прикреплённые к костям персонажа, а не его дочерние объекты, поэтому v3 их не видел. Теперь
  они находятся по точке крепления и скрываются: `NearCamera` — на голове/шее/лице или ближе `CosmeticRadius` (1.5 м) к камере;
  `AllOnSelf` — все эффекты на себе. Прикреплённые предметы (оружие и т. п.) скрываются при `ShowBody = None`.

**Первое лицо v5 (0.5.0) — чёрная рамка вокруг мира:** в v4 3D-мир рисовался только в прямоугольнике по центру, вокруг — чёрное.
Статически причина не подтвердилась (игра сама `Camera.rect` не меняет, кроме NGUI `UIViewport`; `CameraRotator` каждый кадр
строит проекцию из текущего FOV; вспомогательная камера `CamDepthXRay` копирует FOV/near/far только при включении), поэтому v5:
- держит `Camera.rect` камеры = весь экран (`ForceFullViewport`, `UIViewport` для неё пропускается), подстраивает FOV/near/far
  дочерних камер (`SyncHelperCameras`), выключает меши, прикреплённые к камере (`HideCameraAttachedRenderers`); всё
  восстанавливается по F8;
- пишет в журнал полное состояние всех камер до входа, сразу после и через ~1 с (`[cam before first person]`, `[cam first person entered]`,
  `[cam first person +1s]`): rect, pixelRect, target texture, clear, cullingMask, near/far, фактический FOV проекции, компоненты;
- **F10** (`BisectKey`, секция `FirstPersonDiagnostics`) в первом лице по очереди отменяет одно изменение: FOV игры, near игры, far игры,
  без неба, туман игры, layerCullDistances игры, без защит v5, затем выключает каждый компонент камеры по одному. На каком шаге
  рамка пропала — видно на экране (`bisect N/M: ...`) и в журнале (`bisect N state: ...`). Найденный компонент можно выключать
  постоянно через `DisableCameraComponents` (имена через запятую); FOV — `FieldOfView`; небо — `FirstPersonSky.Enabled = false`.
- Прицел с тёмной обводкой (`CrosshairOutline`).

**Вид от третьего лица v6 (0.6.0) — «как в WoW», из-за спины / через плечо:**
- **F7** (`ThirdPerson.ModeKey`) переключает по кругу: вид сверху (игра) → третье лицо → первое лицо → вид сверху.
  **F8** по-прежнему сразу включает/выключает первое лицо (из третьего лица — переход в первое).
- В третьем лице работает всё управление первого лица: **WASD** (относительно направления камеры), **G**, переназначения умений
  (`FpSpellKeys`), ЛКМ = атака/использование, свободный курсор в окнах и чате, туман/небо/FOV/полноэкранная защита, плавность.
  Переход между первым и третьим лицом не сбрасывает туман/небо/FOV; выход в вид сверху возвращает всё (и игровой зум).
- Схема мыши `ThirdPerson.LookMode`:
  - `WoW` (по умолчанию): курсор виден. **Зажать ПКМ** — обзор мышью, направление ходьбы поворачивается вместе с камерой;
    **зажать ЛКМ** — облёт камеры вокруг персонажа без смены направления ходьбы; **обе кнопки** — идти вперёд
    (`BothButtonsForward`). Клик ЛКМ без движения мыши — обычный клик игры по тому, что под курсором (атака / использование),
    наведение на цели и прицел наземных умений — настоящим курсором. **G** — взаимодействие с тем, что под курсором.
    Когда идёшь после облёта ЛКМ, камера плавно возвращается за спину (`AutoFollow`, `AutoFollowSec` 0.5).
    **CapsLock** (`MouseLockKey`) — постоянный обзор мышью с прицелом (как Shooter), повторное нажатие — обратно.
  - `Shooter`: курсор захвачен и держится на прицеле, как в первом лице (`Crosshair`).
- **Колесо мыши** — расстояние: `MinDistance` 1.5 м … `MaxDistance` 15 м, по умолчанию `Distance` 5 м, плавно (`ZoomStep`, `ZoomSmoothing`).
- **Плечо:** `ShoulderOffset` 0.6 м вправо (0 — строго за спиной), **V** (`ShoulderSwapKey`) — сменить плечо.
  Высота точки вращения `PivotHeight` 1.6 м, наклон `PitchMin` −40° … `PitchMax` 70°, начальный `DefaultPitch` 15°,
  `FieldOfView` 70, плавность `PositionSmoothingMs` 60.
- **Столкновения камеры:** `Collision` (вкл.) — луч-сфера (`CollisionRadius` 0.25 м) от точки вращения к камере по слоям
  `CollisionLayers` (по умолчанию `Default, Ground, GroundNoXRay, XRay, NO_XRAY, IgnoreClickDecal, IgnoreClickDecalAndXRay, MAP_PROP`;
  юниты, свой персонаж, триггеры и вода не мешают). Камера сразу придвигается к препятствию (зазор `CollisionMargin` 0.1 м)
  и плавно отъезжает обратно (`CollisionReturnSpeed` 4). В строке состояния — `(blocked)`.
- **Скрытие персонажа:** если камера ближе `FadeDistance` (1 м) к персонажу, его модель и эффекты рядом скрываются, дальше — снова видны.
- Строка внизу слева: режим (WoW/Shooter), состояние курсора, расстояние, плечо; **F1** — подсказки по клавишам для текущего режима.
- Журнал: `third person: look ..., distance ..., collision on mask 0x... [Default=0, Ground=..., ...]` (какие слои найдены),
  `collision probe works (SphereCastNonAlloc)`, `camera pulled in by '<коллайдер>' (layer N) at X m`, `camera within 1.0 m ... character hidden`,
  `third person click: HandleInputActions mask ...`, `third person: interact (G) -> ... screen x,y`, ошибки `Physics.SphereCastNonAlloc failed`.

**v7 (0.7.0) — производительность и ПКМ в третьем лице:**
- **ПКМ в WoW-режиме** — только обзор: нажатие и удержание правой кнопки больше не доходят до игры (раньше игра на удержание ПКМ
  вела персонажа к курсору — флаг `0x200`). Если ПКМ отпущена без движения мыши (≤ `RightClickMaxDragPixels` 6 пикс., ≤
  `RightClickMaxSeconds` 0.6 с), игра получает свой правый клик (атака того, что под курсором; `RightMouse = None` — ничего).
  ПКМ + WASD — ходьба относительно камеры, ЛКМ + ПКМ — вперёд, отпускание любой кнопки — стоп. Если персонаж всё же пошёл в
  первые 1.5 с удержания ПКМ без клавиш — мод останавливает его (`StopMovementAction`, строка в журнале).
  Причина бага: перехват `HandleInputActions` не ставился вообще (ошибка HarmonyX «Cannot get result from void method»: префикс
  ActionBarsMod на этом же void-методе объявляет `__result`, и неудачный патч остаётся в общем списке метода). Фильтр кликов
  перенесён в postfix `LocalInputHandler.EvaluateActionsByInput` (маска действия до `HandleInputActions`). Заодно в первом лице
  и Shooter наконец работают задуманные правила: клик не ведёт персонажа (`ClickMove = false`), ЛКМ = атака + использование.
- **Пресет `[Performance] Preset = Performance`** (по умолчанию) для первого/третьего лица: дальняя плоскость 600 м и ещё ниже —
  до конца тумана (`FarClipFitFog`: конец тумана × 1.5 + 50 м, не меньше 250 м; дальше всё равно сплошной туман), `lodBias` 1.5,
  `layerCullDistances` игры не сбрасываются, поиск эффектов раз в 60 кадров, поиск по сцене раз в 10 с, всё по частям (32 объекта
  за кадр). `Preset = Custom` — старые параметры (`FirstPersonFarClip`, `LodBias`, `DisableLayerCullDistances`, `EffectsScanFrames`).
- **Оптимизации:** поиск объектов `FindObjectsByType(..., SortMode.None)` вместо `FindObjectsOfType` (без сортировки), обход
  результата по частям по «сырым» указателям (без обёртки на каждый объект), «мой ли это объект» — по множеству указателей
  трансформов персонажа вместо подъёма по родителям, кэш классификации рендеров/эффектов/коллайдеров, IMGUI рисует только на
  Repaint с кэшированными `GUIContent`/стилями, проверки окна/viewport/FOV/тумана реже, без строк и массивов каждый кадр.
- **Профайлер** (`ProfileLog = true`, `ProfileIntervalSec` 10): каждые 10 с и при смене режима строка
  `CameraMod perf [third person, 10.0 s, 590 frames]: fps 59.0 (frame avg 16.9 ms, max 40.1 ms); mod 0.21 ms/frame, pose 0.06, collision 0.03, effects 0.02 (max 1.1), gui 0.02 x2.0/f, click ... | render: far 368, fov 70, fog on end 212, shadows 120 m x4 cascades, lodBias 1.50, layerCull game, preset Performance, ...`
  — fps и время кадра режима, сколько мс на кадр тратит сам мод по частям (и худший вызов), и настройки отрисовки, которые
  стоят кадров. Для сравнения пришлите строки `CameraMod perf` и `GraphicsMod perf` для вида сверху, третьего и первого лица.

**Настройки:** `<папка игры>\BepInEx\config\albionlocal.camera.cfg` (создаётся при первом запуске; клавиши, множители,
чувствительность, пороги наклона, `General.Enabled`). Изменения применяются после перезапуска клиента.

**Отключить:** удалить `<папка игры>\BepInEx\plugins\CameraMod.dll` (или `General.Enabled = false` в конфиге).

**Журнал:** строки `CameraMod: ...` в `<папка игры>\BepInEx\LogOutput.log` — `hooked ActorCameraController.LateUpdate`,
`camera active ... target=...`, `first-person ON, head: ...`, `first-person OFF ...`, ошибки (`error in ...`).
Первое лицо v3: `hooked dvh.f(KeyCode,EventModifiers,bool)`, `first-person move: dir=... via ... -> ...`,
`MoveMethod Auto switched to ClickMove` / `InputAction works`, `game hotkey W ... swallowed`, `Alpha3 -> game hotkey W down`,
`first-person effects ...`, `hid own overhead GUI ...`, `first-person sky: ...`, `sky dome shader ...`.
Первое лицо v4: `hooked LocalInputHandler.HandleInputActions`, `first-person click: HandleInputActions mask 0x.. -> 0x..`,
`interact (G) -> ...`, `game window open (...) -> cursor freed` / `game windows closed`, `window check: alignment ... skipped`,
`Vfx on you '...' socket '...'`, `ConstrainableObject on you ...`, `first-person effects summary: ...`, `crosshair above the ground limit ...`.
Первое лицо v5: `hooked UIViewport.LateUpdate`, `[cam ...] camera N/M (MOD CAMERA): ...`, `behaviours: ...`, `renderer under the mod camera ...`,
`renderers within 1 m of the eye ...`, `first person view: rect ...`, `helper camera ...`, `disabled camera-attached renderer ...`,
`camera rect ... -> full screen`, `camera state changed: ...`, `bisect N state: ...`.
v7: `hooked LocalInputHandler.EvaluateActionsByInput` (вместо `HandleInputActions`), `third person click: right press mask 0x28 -> 0x0 (look: press held back)`,
`... right release mask 0x200 -> 0x28 (click: right press action sent on release)` / `-> 0x0 (look drag N px / T s: no click)`,
`... left press mask 0x454 -> 0x45C`, `the character started walking while the right button (look) was held -> StopMovementAction`,
`far clip 600 -> 368 m (fog end 212 m, preset Performance)`, `CameraMod perf [...]: ...` (раз в 10 с).

**Известные ограничения:**
- Вид от первого лица — эксперимент: клики по земле/целям идут лучом из камеры, поэтому ходьба и выбор целей
  мышью работают странно; возможны дыры в мире, видимые изнутри объекты, обрезанные тени и LOD — игра
  рассчитана на вид сверху. Голова ищется через Animator (humanoid), иначе по имени кости с «head», иначе
  позиция игрока + 1.7 м.
- Сильное отдаление/наклон к горизонту показывают незагруженные или обрезанные участки карты, туман и тени
  настроены под стандартный ракурс.
- Alt + правая кнопка в виде сверху может одновременно вызвать игровое действие правой кнопки; лучше средняя кнопка.
- ActionBarsMod (на 20.10) ставит на `HandleInputActions` префикс с `__result`, из-за чего этот метод не может перехватить ни один
  мод; CameraMod его больше не использует.
- Внутри зданий игра переключается на свой «внутренний» ракурс; добавочный зум и поворот применяются поверх него.
- Наложение статуса на экране (IMGUI) требует внедрения класса; если оно не удалось — статус только в журнале.

## GraphicsMod (тени и дальность прорисовки сверх настроек игры)

Исходники: `GraphicsMod\` (находки — `GraphicsMod\NOTES.md`). Сборка: `tools\build-client-mods.ps1` (готовая DLL — в `dist\`). От CameraMod не зависит, работает вместе с ним.

**Что делает.** Игра использует встроенный конвейер Unity (не URP), отложенное освещение (Deferred). Свои настройки графики
игра применяет в `GraphicOptions.d()` (сначала `QualitySettings.SetQualityLevel`, потом значения из меню), а дальность теней
ещё и уменьшает при приближении камеры (`GraphicOptions.b(zoom, ...)`, вызывается из зума камеры). Мод после каждого такого
применения (Harmony postfix) и раз в кадр (дешёвая проверка: меняет только то, что отличается) ставит свои значения:
- дальность теней `ShadowDistance` (150 м); когда камера низко над игроком (< `FirstPersonHeight` = 5 м — первое лицо,
  вид из-за плеча, в том числе от CameraMod) — `ShadowDistanceFirstPerson` (150 м, раньше 250; уже созданный конфиг хранит
  старое значение), но с `[Performance] LowCameraPreset = Performance` (по умолчанию) не больше `LowCameraShadowDistance` (120 м):
  низкая камера видит намного больше объектов, отбрасывающих тень, чем вид сверху; `LowCameraPreset = Config` — без ограничения;
- 4 каскада теней с точками раздела `CascadeSplits` (0.04/0.12/0.35 → 6/18/52 м при 150 м), разрешение VeryHigh,
  проекция StableFit (тени не дрожат при движении камеры), мягкие тени (и у направленных источников Hard → Soft),
  тени включаются, даже если в меню игры они выключены (`ForceShadowsOn`);
- `LodBias` 2 (только повышает), анизотропная фильтрация ForceEnable, сглаживание SMAA High в PostProcessLayer
  (MSAA невозможно при Deferred);
- персонажи/мобы: скин-меши с выключенной отбрасываемой тенью получают её (`CharacterShadows`; модели, у которых уже есть
  меш «только тень», не трогаются). Код игры тени персонажам не выключает — это проверка на данные префабов.
- пресет `Preset = UltraShadows`: 300 м (низкая камера 400 м), 4 каскада с более плотными разделами, VeryHigh, LodBias 3.

**Клавиши:** `F9` — включить/выключить значения мода (выключение возвращает значения игры: тени, дальность, каскады,
LOD, анизотропия, сглаживание, источники света, тени персонажей) — для сравнения «было/стало».

**Настройки:** `<папка игры>\BepInEx\config\albionlocal.graphics.cfg` (создаётся при первом запуске; применяются после
перезапуска клиента). `0`/`-1`/`Game` у параметра = оставить значение игры. Дополнительно: `ShadowStrength` (темнота теней,
игра ставит её по времени суток), `LightShadowResolution`, `ShadowBias`/`ShadowNormalBias`, `PixelLightCount`,
`AntiAliasing` (Game/Off/FXAA/SMAA/TAA), `StartActive` (включены ли значения мода при запуске).

**Отключить:** `F9` в игре (до перезапуска), `General.Enabled = false` в конфиге или удалить
`<папка игры>\BepInEx\plugins\GraphicsMod.dll`.

**Журнал** (`GraphicsMod: ...` в `LogOutput.log`): `hooked ...` (5–6 перехватов), `render pipeline ... main camera path ...`,
`[at start (before mod)] ...`, `mod values ON (...)`, `[after apply] ...`, `game graphics options: ...` (значения меню игры),
`game applied its graphics options: ...`, `[after re-apply] ...`, `[in world, mod values] ...`, `re-applied after game change (...)`,
`camera low/high ... -> shadow distance ...`, `character shadows: ...`, `mod values OFF ...` / `[game values] ...`, ошибки `error in ...`.
0.2.0: профайлер (`[Performance] ProfileLog = true`, `ProfileIntervalSec` 10) — строка
`GraphicsMod perf [600 frames, fps 59.8, camera low]: frame check 0.004 ms/frame, driver 0.010 ms/frame, light scan ..., character scan ... (max N ms); shadows 120 m x4, lodBias 1.5, lights tracked 2, character meshes seen N`.
Проверка в кадре теперь раз в 4 кадра (игра меняет тени только в перехваченных методах), поиск источников света раз в 10 с,
поиск персонажей раз в 5 с без сортировки и только по новым скин-мешам.

**Ограничения:** тени дальше ~150–300 м стоят кадров (4 каскада × 4096 на большом расстоянии); разрешение карты теней выше
VeryHigh недоступно (`shadowCustomResolution` вырезан из сборки); `maximumLODLevel`, `shadowmaskMode`, `antiAliasing`
(MSAA) в сборке вырезаны. Мобы/игроки дальше ~40 м не приходят с сервера (см. `Visibility` в `config/world.jsonc`),
так что их тени тоже не видны. Туман на дальности — дело CameraMod (только в первом лице).

## ActionBarsMod (две дополнительные панели способностей от экипировки)

Исходники: `ActionBarsMod\`. Сборка: `tools\build-client-mods.ps1` (готовая DLL — в `dist\`).
Работает только с нашим сервером (протокол — в закрытом рабочем каталоге автора,
`analysis\work\stageN\extrabars\SPEC.md`): после каждого входа в зону (JoinFinished) мод шлёт серверу «привет» (op 9001), и только
тогда сервер присылает ему панели (event 9001), откаты (9002), отказы (9003) и каталог явных записей «вещь → доп. способности»
(9004); с v0.3 (протокол 2) мод спрашивает сервер про любую вещь (op 9003) и получает её доп. способности по правилам с причиной
каждой (event 9005), а в 9001 есть причина для каждого слота (ключ 11). Клиент без мода ничего этого не видит.

**Что делает:** над игровой панелью умений (Q W E R D F) ставит две строки по 6 кнопок (сколько строк и кнопок — решает сервер,
`Bars`/`BarSize`). В кнопках — способности, которые дают надетые вещи.
- **Вид кнопок (v0.2, `Layout.Style`):** `Native` (по умолчанию) — кнопки *это и есть кнопки игры*: мод клонирует игровую кнопку
  MainHand1 (NGUI: рамка, фон, иконка, заливка отката, цифры отката, подпись клавиши) 12 раз, удаляет из клонов игровые скрипты и сам
  управляет виджетами (иконка из атласа игры через её же поиск атласа `drv.s`, заливка отката, цифры, клавиша). Размер и шаг — как у
  игровых кнопок, ряды стоят ровно над игровой панелью. Если клонирование не удалось — сам переходит на `Atlas`: мод рисует кнопку
  (IMGUI) из тех же спрайтов игры (снимок слоёв игровой кнопки: рамка/фон/откат/шрифт подписи). `Classic` — прежний плоский вид.
- **Подсказка на кнопке (`Tooltips.SpellTooltips`):** `Game` — родная подсказка игры для способности (та же, что у Q–F: название,
  характеристики, описание с цифрами по вашей экипировке); `Mod` — такая же по содержанию, но рисует мод (иконка, название золотом,
  строки характеристик, описание, какая вещь дала, остаток отката); `Off`. `Game` при ошибке сам переходит на `Mod`.
- **Подсказки к вещам (`Tooltips.ItemTooltips`):** при наведении на вещь (инвентарь, экипировка, банк, рынок, добыча, сундуки)
  в игровую подсказку дописывается раздел **«Доп. способности»** (на английском клиенте — «Extra abilities»): название и краткое
  описание каждой способности, которую даёт вещь (цветами NGUI, как в игре; иконки в этой текстовой подсказке игра не умеет). В окне
  информации о предмете рядом с окном появляется панель «Доп. способности» с иконками, названиями и описаниями. v0.3: данные — ответ
  сервера на запрос по вещи и её качеству (op 9003 → event 9005: правила ниже, как если бы вещь была надета), рядом с названием серым —
  откуда способность («невыбранный вариант», «по типу предмета», «зачарование .2», «шедевр», «артефакт»). Ответы кешируются по
  (вещь с `@n`, качество) и сбрасываются при каждой смене панелей (смена экипировки или выбора умения). Пока ответа нет, сразу
  показываются явные записи каталога (9004); если подсказка ещё открыта, когда пришёл ответ, раздел дописывается в неё, иначе — при
  следующем наведении. Окно информации о предмете берёт качество последней наведённой вещи с тем же именем (иначе обычное).
- Красная вспышка и строка над панелями при отказе сервера. Панели прячутся, когда игра прячет HUD (загрузка, нет персонажа, HUD скрыт) и
когда сервер прислал 0 панелей.

**Клавиши (по умолчанию):** нижняя панель — `Shift+1…6`, верхняя — `Ctrl+1…6`; клик мышью по кнопке тоже применяет способность
(клик не уходит в мир — персонаж не пойдёт туда). Пока открыт чат/поле ввода, клавиши не срабатывают. Сами `1`/`2` (зелья/еда) и
любые другие сочетания остаются за игрой: мод глушит в диспетчере горячих клавиш игры только свои сочетания и только если такой
слот есть.

**Как применяется:** по умолчанию (`CastMethod = Auto`) способность кладётся в служебный слот 25 клиента и запускается так же, как
обычная клавиша (`LocalInputHandler.StartCast`): прицеливание, наземные способности по курсору, полоска каста и анимация — как у
обычных умений. Откат слота 25 у клиента сбрасывается, свои откаты мод берёт только из событий сервера. Если этот путь недоступен
(способности нет в таблице клиента и т. п.), Auto шлёт серверу op 9002 (точка под курсором, цель — выбранная), тогда своей анимации/
полоски каста у игрока нет.

**Настройки:** `<папка игры>\BepInEx\config\albionlocal.actionbars.cfg` (создаётся при первом запуске):
- `[General]` `Enabled`; `CastMethod` = Auto / Slot25 / Slot25Direct (слот 25 + каст сразу в точку курсора, без режима
  прицеливания) / Op; `CastAsHotkey` (false: прицеливание завершается кликом); `LocalizedNames`; `LogEvents`.
- `[Layout]` `Style` = Native / Atlas / Classic; `ShowCooldownNumbers`; `Rows` (1–2), `RowGap` (6), `OffsetX`/`OffsetY` (сдвиг,
  +Y = выше), `AutoAnchor` (ставить прямо над игровой панелью; без него — 130 px от низа экрана + OffsetY); для Classic ещё
  `ButtonSize` (48), `Spacing` (4), `AutoSize`, `Opacity` (0.1–1); `ShowKeys`, `ShowTooltips`, `BlockClicksUnderBars`.
- `[Tooltips]` `SpellTooltips` = Game / Mod / Off; `ItemTooltips` (раздел в подсказках вещей и панель у окна предмета);
  `ItemTooltipColors` (false — если в подсказке видны коды вида `[c8a065]`); `ItemTooltipDescriptionChars` (160; 0 — целиком).
- `[Keys]` `Bar1Slot1…Bar2Slot6`: модификаторы `Shift`/`Ctrl`/`Alt` + имя клавиши Unity: `Shift+Alpha1`, `Ctrl+Q`, `Alt+3`, `Mouse3`;
  пусто или `None` — без клавиши.

**Откуда берутся способности (сервер, правила `Rules` в `content\extraspells.json`, решение 20.10):** каждая надетая
официальная вещь даёт способности из своих же данных, так что хорошо одетый персонаж заполняет все 12 ячеек.

| Источник | Доп. способности (по умолчанию) |
|---|---|
| Основное оружие | 2 = **невыбранные** варианты его собственных умений Q/W/E (по кругу Q, W, E; в порядке списка) |
| Вторая рука | 1 по типу: щит — BLOCK / TAUNT / STONESKIN; книга — EMERGENCY_SHIELD / LIFESAVIOR / MAXHEALTHBUFF; сфера — ENERGYSHIELD2; череп демона — BLOODLUST; тотем — MAXHEALTHBUFF; факел — FLAMESHIELD / HASTE / SPEEDCASTER; рог — HOWL; талисман — PURGINGSHIELD2; лампа — RETALIATE2 (первая ещё не занятая) |
| Шлем, броня, ботинки | по 1 = невыбранный вариант своего умения (R/D/F) |
| Плащ | 1: SPRINT (у плащей только пассивки) |
| Сумка | 1: SELF_CLEANSE, иначе ENERGY_BARRIER |
| Маунт | 1 (работает пешком): SPRINT_CD_REDUCTION / SPRINTEOT / SPRINTHOT (свои умения маунтов — для езды, не берутся) |
| Зачарование | оружие .2 и выше → +1; броня .3 и выше → +1 (ещё невыбранные варианты той же вещи) |
| Качество | Шедевр (5): оружие, шлем, броня, ботинки → по +1 (для «Отличного» — запись с `"Min": 4`) |
| Артефакт | +1 артефактному оружию / второй руке / броне (в рецепте ресурс `*_ARTEFACT_*`): сначала его уникальные варианты (латы Хранителя → FORCESHIELD); у артефактного оружия уникальное умение — это его E, поэтому +1 невыбранный вариант |

Сначала базовые способности всех вещей (оружие, вторая рука, шлем, броня, ботинки, плащ, сумка, маунт), потом бонусы; что не влезло
в 12 ячеек — отбрасывается. Пропускаются переключатели/пассивки, умения, уже стоящие на панели Q–F, уже выданные и (`RespectUnlocks`)
закрытые умения, если доска судьбы открыта не полностью. Пример: T6 меч + щит + латный сет + плащ + сумка + лошадь = 9 ячеек; меч .2
шедевр и латы .3 добавляют ещё 3 = 12. Всё настраивается в файле (`Slots`, `Enchantment`, `Quality`, `Artifact`; там комментарии).

**Явные записи (перекрывают правила для названной вещи):**
- `content\extraspells.json` `"Items": { "T4_MAIN_SWORD": ["SPRINT"], "T*_HEAD_CLOTH_SET1": [{ "spell": "FLEE", "bar": 2,
  "position": 1 }] }` — только активные способности (не переключатели/пассивки), `*`/`?` в именах вещей; вещь из записи даёт ровно
  это вместо правил. По умолчанию записей нет. После правки — `.extrabar reload`.
- Студия (веб-панель, `/studio`): в редакторе предмета раздел **«Доп. способности»**, затем Generate — пишет
  `mods\<пак>\server\extraspells.json` (пак должен быть в `Mods:Packs`).
- GM в игре: `.extrabar list`, `.extrabar explain` (по каждой надетой вещи: какое правило, бонусы, уникальные варианты артефакта,
  что выдано и что не влезло), `.extrabar set <1-12> <SPELL|->` (временно поставить способность в слот), `.extrabar clear [n]`,
  `.extrabar reload`.

**Что проверить:**
1. Войти в мир в плаще (`T4_CAPE`) — над игровой панелью две строки кнопок того же вида, что игровые (рамка, фон, шрифт клавиши),
   в первой SPRINT; при наведении — родная подсказка игры о способности. Для сравнения — `Style = Atlas` и `Classic`.
2. `Shift+1` — рывок с обычной анимацией и полоской; на кнопке идут секунды отката; `1` (зелье) по-прежнему работает.
3. `.extrabar set 7 <какая-нибудь наземная способность>` — кнопка в верхнем ряду (`Ctrl+1`), применение по курсору.
