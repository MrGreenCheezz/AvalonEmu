# Моддинг: свои предметы и способности (modkit)

Краткая инструкция. Подробно (на английском): `server/tools/AlbionLocal.ModKit/README.md`.

Modkit собирает «паки» — папки `server/mods/<пак>/` — и ставит их в клиент `game-local`.
Сервер и клиент читают одни и те же файлы GameData, поэтому новые предметы и способности
видны обоим одинаково.

## Что можно и чего нельзя

Можно:
- новые предметы (оружие, броня, ресурсы…) на основе существующих моделей и иконок;
- новые способности, собранные из существующих эффектов (рывок, урон, замедление, поле, щит…);
- рецепты крафта и станки, где предмет крафтится;
- названия и описания (EN, RU и другие языки);
- где предмет выпадает (босс, моб, сундук, шанс) — только на сервере, клиент не меняется;
- изменить атрибуты официальных предметов и способностей (`<set>`).

Нельзя: новые 3D-модели, иконки, анимации, эффекты и звуки — только те, что уже есть в клиенте.
Новому предмету обязательно указать `mesh="..."` (модель) и `uisprite="..."` (иконку) какого-нибудь
официального предмета, например `mesh="T6_MAIN_SWORD" uisprite="MAIN_SWORD"`.

## Команды

Всё запускается из папки `server/`:

```
dotnet run --project tools/AlbionLocal.ModKit -- extract                 # XML-файлы для справки в data/modkit-extract/
dotnet run --project tools/AlbionLocal.ModKit -- check example-blade     # проверить пак, ничего не записывает
dotnet run --project tools/AlbionLocal.ModKit -- build example-blade     # собрать и установить в game-local
dotnet run --project tools/AlbionLocal.ModKit -- status                  # что установлено
dotnet run --project tools/AlbionLocal.ModKit -- restore                 # вернуть официальные файлы
dotnet run --project tools/AlbionLocal.ModKit -- icons                   # один раз: иконки для веб-панели
```

`icons` читает (только чтение) атласы клиента `ItemAtlas`, `ItemAtlas_01`, `ItemAtlas_02`, `SpellAtlas` из
`game/Albion-Online_Data/resources.assets` и пишет PNG по одной на спрайт + `index.json` в `data/icon-cache/`
(~20 с, ~2900 иконок, ~70 МБ). Папка не попадает в git и никуда не публикуется: это ресурсы клиента.
После обновления клиента запустите ещё раз. Опции: `--assets <файл>`, `--out <папка>`, `--atlas <имя,имя>`.

`build` каждый раз собирает заново из чистых официальных файлов и заменяет прошлую сборку:
перечисляйте сразу все нужные паки (`build pack1 pack2`).

Чтобы сервер включил дропы пака: `--Mods:Packs=example-blade` при запуске сервера или
в `config/albionlocal.json`: `"Mods": { "Packs": ["example-blade"] }`.

## Как написать пак

1. `extract` — посмотреть, как устроены `items.xml`, `spells.xml`, `buildings.xml`, `localization.xml`.
2. Скопировать `mods/example-blade` в `mods/мой-пак`, поправить `pack.json` (Name, Version, Client).
3. Файлы патчей называются как файл GameData: `items.xml` → `items.bin`, `spells.xml` → `spells.bin` и т.д.
   Внутри `<patch>` операции:
   - `<add>` — добавить новый элемент в конец (новое `uniquename`);
   - `<add uniquename="T6_FORGE" path="craftingitemlist">` — добавить дочерний элемент (например, предмет в станок);
   - `<replace uniquename="X">` — заменить элемент целиком;
   - `<set uniquename="X" attr="..." value="..."/>` — поменять один атрибут (`path=` для вложенного);
   - `<remove uniquename="X" path="..."/>` — удалить вложенный элемент;
   - в `localization.xml`: `<entry tuid="@ITEMS_X"><text lang="EN-US">…</text><text lang="RU-RU">…</text></entry>`.
4. Названия: предмет — `@ITEMS_<uniquename>` и `@ITEMS_<uniquename>_DESC`; способность — её
   `namelocatag` / `descriptionlocatag`.
5. `check` — исправить ошибки, затем `build`, запустить сервер и клиент.

Удалять официальные предметы/способности нельзя: клиент нумерует их по порядку в файле, и номера
идут по сети. Новые всегда добавляются в конец; `check` проверяет, что ни один официальный номер
не сдвинулся, и показывает номера новых.

## Редактор в веб-панели (без XML вручную)

Веб-панель сервера (`http://127.0.0.1:8080/`, вход аккаунтом уровня Admin) → **Mods**:

- **Каталог предметов и способностей** — поиск по имени (EN/RU) и uniquename, фильтры по тиру, виду и слоту;
  у предмета видны характеристики, способности, рецепт, станки и откуда он падает (официальный лут и дропы паков).
  Первое открытие читает данные клиента 10–30 с.
- **Паки** — список `server/mods/`, создание нового (имя из a-z, 0-9, -), страница пака: новые предметы и
  способности, прочие изменения, дропы.
- **Clone & edit item** — взять официальный предмет как шаблон: новое имя, названия и описания EN+RU, все
  атрибуты шаблона полями с его значениями (урон, скорость, дальность, прочность, вес, item power…), слоты
  способностей (официальные или новые из пака), рецепт (серебро, время, фокус, ингредиенты, станки), дропы
  (мобы/сундуки по шаблону имени, категория, шанс). Модель и иконка всегда шаблона; уровни зачарования не копируются.
- **Конструктор способностей** — склонировать способность (по желанию вместе с её под-способностями, тогда их
  числа тоже можно менять), править все числа (перезарядка, энергия, каст, дальность, радиусы, длительности,
  урон/лечение) и добавлять блоки эффектов из других способностей (например, замедляющее поле из
  `ICEROCK_EXPLODE_FROST_PATH`) или удалять их.
- **Validate** (= `check`, ошибки и предупреждения прямо на странице), **Preview** (файлы пака и отличия от
  шаблонов), **Install** (= `build` выбранных паков в game-local), **Restore** (= `restore`).

После Install/Restore **перезапустите сервер и клиент сами** — панель сервер не перезапускает. Для дропов
добавьте пак в `Mods:Packs`. Все изменения — только для Admin, с CSRF-токеном и строкой аудита в логе.

Иконки: после `modkit icons` каталог, страницы предмета/способности, форма клонирования (иконка шаблона — её
получит и новый предмет) и конструктор способностей показывают иконки клиента (`/admin/icons/<спрайт>.png`,
только для Admin). Без кэша страницы показывают подсказку «запустите modkit icons» и работают без картинок.

## Студия (новый визуальный редактор)

Веб-панель → **Studio** (`http://127.0.0.1:8080/studio`, вход аккаунтом Admin; из `/admin/mods` есть ссылка).
Одностраничное приложение: слева пакет и его записи, в центре редактор, справа живой предпросмотр.

- **Новое… → копия из каталога**: окно поиска с иконками (имя, EN/RU, фильтры по тиру/типу/слоту/категории,
  стрелки и Enter, «Показать ещё») → выбрать предмет или умение → дать уникальное имя. Копировать и вставлять
  имена больше не нужно. То же из **Каталога** (предметы, умения, мобы, списки лута, станции, иконки):
  карточка записи → «Сделать копию…».
- **Редактор предмета**: имя и описание RU/EN, основные характеристики, рецепт (ингредиенты выбором из
  каталога), станции, умения по слотам, дроп (мобы/шаблоны, сундуки, категория, шанс в %), все атрибуты шаблона
  полями с подсказками и кнопкой «вернуть значение шаблона». **Редактор умения**: числа (перезарядка, энергия,
  каст, дальность…), вложенные умения (официальные или клонировать с ним), все атрибуты блоков эффектов.
- **Справа**: подсказка как в игре (характеристики, умения с описаниями, где {0} заполнены числами), разница с
  шаблоном, итоговый XML, проблемы. Проблемы видны и прямо у полей; кнопка с ⛔/⚠ сверху — центр проблем.
- Сохранение Ctrl+S, отмена/повтор Ctrl+Z/Ctrl+Y, автосохранение несохранённого в браузере (баннер «вернуть»),
  история версий записи (последние 20), переименование с обновлением ссылок, «где используется», удаление с
  проверкой зависимостей.
- **Сгенерировать** — черновики (`mods/<пакет>/studio/<вид>/<ИМЯ>.json`, они главные) собираются в патч-файлы
  пакета (items.xml, spells.xml, buildings.xml, localization.xml, server/drops.json); то, что сделано классическим
  редактором или руками, не трогается. **Проверить** = генерация + `check` модкита (в фоне, с прогрессом).
  **Установить…** = генерация + `build` выбранных пакетов в game-local; **Восстановить…** = `restore`.
  После установки/восстановления **перезапустите сервер и клиент**.
- Меню пакета «⋯»: новый, переименовать, выгрузить zip (весь пакет) или JSON (черновики), импорт, патч-файлы,
  состояние модкита. Язык интерфейса RU/EN (по умолчанию RU) — переключатель справа сверху.

### Рецепты: выбираете цель, а не поля

**Новое… → По цели (рецепты)** (или карточка «По цели» на главной): карточки целей с короткими описаниями.
Каждая цель — список полей (подпись RU/EN, подсказка, тип, значение по умолчанию, мин/макс, обязательность);
форма слева, справа живой предпросмотр (подсказка как в игре, какие черновики будут созданы, проблемы).
Пустое обязательное поле или число вне диапазона — блокер прямо у поля, «Создать» недоступно.

- **Предметы** (10): одноручное, двуручное оружие, вторая рука, доспех (голова/тело/обувь × ткань/кожа/латы),
  сумка (с пассивкой веса), плащ (с выбранной пассивкой), зелье/еда (эффект официального расходника × сила,
  перезарядка, стопка — эффект создаётся отдельным умением `<ИМЯ>_EFFECT`), инструмент сбора, скакун
  (официальная модель; скорость через свой бафф `<ИМЯ>_MOUNTED`, здоровье, бонус веса), ресурс/трофей/жетон.
  Шаблон — официальный предмет семейства нужного тира (модель, иконка, рецепт, станции, умения).
- **Умения** (14): прямой урон, урон по области, урон со временем, лечение, лечение со временем, щит,
  усиление характеристики, замедление, оглушение/корни/безмолвие, рывок, отбрасывание/притягивание, призыв,
  пассивка, поле на земле (тик — своё умение `<ИМЯ>_TICK`). Каждое собирается из блоков официальных умений
  (например, замедление = удар THREATENINGSTRIKE_HAMMER + блок замедления из HAMSTRINGSWORD_EFFECT); описание
  RU/EN пишется само из чисел.
- **Линейка T4–T8**: тот же предмет для каждого тира, числа заданы для одного тира и пересчитаны по
  официальной кривой семейства (значение шаблона на тире / на опорном тире); черновик на тир. Флажок
  «Уровни зачарования .1–.3» оставляет новому предмету зачарования шаблона.
- **Наборы** (в один клик, с префиксом имён): легендарный босс с уникальным дропом (вариант моба + список лута +
  уникальное оружие с новым умением + правило дропа оружия с босса), линейка T4–T8, набор расходников
  (зелье + еда), элитный лагерь (несколько вариантов мобов + сундучный лут).
- **Помощник значений**: у числовых полей рецептов и у основных характеристик в «Все поля» — официальный
  диапазон того же вида и тира (мин · медиана · макс, полоска с текущим значением) и кнопка «Предложить»
  (медиана).
- Черновик, сделанный рецептом, помнит цель: вкладка **«Цель»** снова показывает форму рецепта; изменение
  пересобирает черновик (заданный дроп сохраняется, вспомогательные умения сохраняются сразу).
- **Блоки умений**: во «Все поля» у умения блок верхнего уровня можно убрать (✕ / «Вернуть»), а «+ Добавить
  блок из умения…» копирует блок любого умения (выбор умения → выбор блока; его параметры — поля).
- **Импорт из классического редактора**: в «Другие новые элементы» у записи с известным шаблоном (editor.json)
  кнопка «Импорт» делает из неё черновик студии.

### Мобы и списки лута — данные сервера

Модкит патчит только items/spells/buildings/localization, поэтому новые мобы и лут — **серверные данные пакета**:
- **Вариант моба** (`mods/<пакет>/server/mobs.json`): официальный моб (модель, имя и умения клиента) с
  множителями здоровья, урона, славы, своими списками лута и шансом появляться вместо шаблона в мире.
  ГМ-команда `.mob variant <ИМЯ> [кол-во]`. Правила дропа предметов могут указывать имя варианта.
- **Список лута** (`server/loot.json`): записи без веса бросают свой шанс, записи с весом делят N выборов;
  запись — предмет (мин–макс) или другой список (этого пакета или из loot.xml).
- Справа у списка/варианта — **симулятор лута**: N бросков/убийств → ожидаемые и выпавшие количества.
- Нужен пакет в `Mods:Packs` и перезапуск сервера; клиент ничего не знает о вариантах (показывает шаблон).

## Пример: example-blade

«Заводной клинок (мастер)» — одноручный меч T6 с моделью и иконкой палаша; крафт в Кузнице
воина (T6–T8): 16 слитков, 8 кожи, 10 рун T6. Способность «Заводной рывок»: рывок, по прибытии
95 физического урона вокруг и поле на 4 с, замедляющее врагов на 35 %. Падает с мировых боссов
с шансом 3 %. Пак не установлен — решаете вы.

## Безопасность и риски

- Файлы `game-local` — жёсткие ссылки на официальный клиент (отдельная папка). Modkit никогда не пишет
  в них: создаёт новый файл рядом, удаляет ссылку и ставит новый файл на её место, затем проверяет,
  что официальный файл не изменился. В `Reverse/game` запись запрещена вообще.
- `restore` снова делает файлы жёсткими ссылками на официальные.
- После обновления официального клиента `build` откажется работать: проверьте паки на новых данных
  и соберите с `--force`. До пересборки (или `restore`) модифицированные файлы обновление не получат.
- Сервер при старте проверяет номера предметов и способностей; если сборка не совпадает с данными,
  он не запустится — пересоберите или сделайте `restore`.
- **Никогда не заходите модифицированным клиентом на официальные серверы.** Он только для локального сервера.

## Плагины (C#)

Плагин — это код на C#, который сервер вызывает на игровые события: вход игрока, смерть моба, урон, лут, крафт,
сбор ресурсов, вступление в группу и т.д. Клиент при этом не меняется. Подробно (на английском, со всем API):
`server/plugins/README.md`; устройство: `analysis/work/stageN/plugins/SPEC.md`.

Плагин — папка `server/plugins/<имя>/`:
- `plugin.json` — имя, версия, автор, описание, `apiVersion` (сейчас 2; плагины с 1 тоже грузятся), `enabled`, `dependencies`;
- `*.cs` — исходники (или готовая DLL: `"assembly": "MyPlugin.dll"`);
- `config.json` — настройки по умолчанию (владелец сервера переопределяет их в `data/plugins/<имя>/config.json`).

Плагин ссылается только на сборку `AlbionLocal.Plugin.Api` (интерфейсы `IPlugin`, `IPluginEvents`, `IServer`,
`IPlayer`, `IMob`…), а не на внутренности сервера. Сервер сам собирает исходники локальным `dotnet build` в
`data/plugins-bin/<имя>/` (только когда они изменились) и грузит каждый плагин в отдельный выгружаемый
`AssemblyLoadContext`.

Как включить:
- в `config/albionlocal.json`: `"Plugins": { "Enabled": true, "List": ["welcome"] }` (`Enabled` уже включён в пресете pve;
  без `List` грузятся плагины с `"enabled": true` в их `plugin.json`);
- или прямо в игре (Admin) / в консоли сервера: `.plugins enable welcome` (до перезапуска).

Команды: `.plugins list` (что найдено и в каком состоянии), `.plugins reload <имя>` (выгрузить, пересобрать, загрузить —
без перезапуска сервера), `.plugins enable <имя>`, `.plugins disable <имя>`. Собрать без запуска сервера:
`dotnet run --project src/AlbionLocal.Server -- --plugins-build`.

Что умеет плагин: подписываться на события; писать игроку / в зону / всем; выдавать и забирать предметы, серебро,
славу; телепортировать; вешать и снимать баффы; ставить мобов и мировых боссов; запускать мировые события (вторжения);
менять урон и добавлять предметы в лут; читать информацию об игроках и мире; добавлять свои чат-команды; хранить
данные (`storage.json`) и читать свой конфиг; таймеры «каждые N секунд» и «через N секунд».

Безопасность: всё выполняется в мировом потоке; любой вызов плагина обёрнут в try/catch. Исключение пишется в лог,
после `Plugins:MaxErrors` (10) ошибок плагин отключается, а сервер работает дальше. Обработчик дольше `Plugins:SlowMs`
(50 мс) отмечается в логе — обработчики должны быть короткими (бесконечный цикл всё равно подвесит сервер).

Мод-пак может нести плагины: `mods/<пак>/plugins/<имя>/` грузятся вместе с паком, если пак указан в `Mods:Packs`.
Так «мод» = патчи данных + дропы + плагины в одной папке.

Примеры (выключены по умолчанию):
- `plugins/welcome` — приветствие при входе (текст из конфига), команда `.motd` (ГМ: `.motd set <текст>`);
- `plugins/bounty-hunter` — раз в N минут объявляет награду за элитного моба в зоне с игроками; убивший получает
  серебро и славу, объявление всем, таблица лидеров хранится между перезапусками; команда `.bounties`;
- `plugins/example-spells` (API v2) — свой скрипт для Clockwork Dash (поле замедления), быстрый галоп ночью, меч с +10 %
  урона при здоровье ниже 30 %.

### API v2: своя логика для заклинаний, баффов, оружия и маунтов

Версия 2 добавляет к событиям **хуки** (`Hooks`) и **действия** (`Game`) — по образцу tswow. Каждый хук вешается либо
на всё, либо на один id (uniquename заклинания, баффа, предмета, маунта или моба):
`Hooks.Spells.OnCheckCast(a => …)` или `Hooks.Spells.OnCheckCast("FIRESTAFFBOLT2", a => …)`. Если хук никто не слушает,
он почти ничего не стоит. Единый шаблон: `Cancel(причина)` — запретить (клиент получает обычный отказ, причина
приходит игроку в чат), `PreventDefault()` — не выполнять стандартный эффект, `Mutable<T>` — значение, которое можно
поменять (`Get`/`Set`), `OnCalc*` — формулы.

- **Заклинания** (`Hooks.Spells`): `OnCheckCast` (отменить каст), `OnCast` (каст прошёл; и у мобов), `OnCancel`
  (прерван/отменён), `OnBeforeHit` / `OnAfterHit` (попадание; можно отменить эффекты из spells.xml), `OnEffect` (заклинание
  действует на конкретную цель — можно отменить для неё), `OnDamageEarly` / `OnDamageLate` (урон и лечение по каждой цели —
  можно изменить число), `OnTick` (тик канала), `OnAreaCreate` / `OnAreaTick` (зоны на земле). В аргументах: кастер, цель,
  заклинание, слот (Q/W/E, броня, шлем, обувь, зелье, еда, маунт) и предмет, который дал заклинание.
- **Скриптовые заклинания**: `Hooks.Spells.Register("MY_SPELL", new SpellScript { OnCast, OnHit, OnTick })` — плагин сам
  реализует заклинание на сервере (по умолчанию эффекты из spells.xml не выполняются, `ReplaceEffects = false` — добавить к
  ним). Связь мод-пака и плагина — **только по имени**: пак добавляет заклинание в spells.xml (иконка, анимация, каст,
  кулдаун, энергия — для клиента) и предмет, который его даёт; плагин регистрирует скрипт с тем же uniquename. Плагин можно
  положить в `plugins/` самого пака — тогда данные и логика едут вместе.
- **Баффы** (`Hooks.Buffs`): `OnCheckApply` (не дать наложить), `OnApply`, `OnStackChange`, `OnTick`, `OnRemove` (истёк,
  снят, очищен); у баффа свои данные (`buff.GetData`), список баффов юнита — `unit.Buffs`.
- **Предметы и оружие** (`Hooks.Items`): `OnEquip` / `OnUnequip` (и при входе в игру), `OnWeaponSwap`, `OnBreak`
  (прочность 0), `OnCalcPassives` (добавить свои бонусы статов, пока надет предмет).
- **Маунты** (`Hooks.Mounts`): `OnCheckMount` (запретить), `OnMountStart`, `OnMounted` (можно сменить бафф галопа —
  скорость), `OnMountCancel`, `OnDismount`, `OnMountDamage` (изменить урон по маунту), `OnMountSpell`.
- **Юниты** (`Hooks.Units`): изменение здоровья и энергии, вход/выход из боя, подъём после нокдауна, `OnReload`.
- **Формулы** (`Hooks.Formulas`): время каста, кулдаун, стоимость энергии, лечение, угроза, слава за убийство, серебро,
  сила предмета (IP).
- **Данные и таймеры на юните**: `unit.GetData(key, () => …)`, `unit.AddTimer(задержка, повторы, …)` — живут, пока жив
  юнит, и очищаются при перезагрузке плагина; после `.plugins reload` плагин получает `OnReload` для всех игроков и мобов.
- **Действия** (`Game`): урон и лечение, наложить/снять бафф по имени заклинания (со своей длительностью и стаками),
  отбросить/притянуть/рывок/телепорт (стены учитываются), своя зона на земле с колбэком на каждый тик, призыв моба,
  модификаторы статов, кулдауны (сбросить/поставить), выполнить заклинание из spells.xml, прервать каст, статы юнита.

Полный справочник — `server/plugins/README.md`, раздел «API v2».

Правила без кода (ниже) работают поверх тех же событий, хуков и действий.

### Смена способности в слоте

Плагин или правило может поменять способность в слоте надетого предмета — как игрок в окне выбора способностей:
`player.SetSlotSpell(SpellSlot.Q, "CLEAVE")`. Слоты: Q, W, E, R (броня), D (шлем), F (обувь), зелье, еда и пассивки
(`WeaponPassive`, `ArmorPassive`, `HeadPassive`, `ShoesPassive`, `CapePassive`, `BagPassive`, `MountPassive` …).
Режим `FromItemList` (по умолчанию) — только варианты этого предмета; `Any` (**экспериментально**) — любая способность того же
вида: сервер её кастует, клиент показывает её на панели (иконка, подсказка) и кастует по id, но в окне предмета ни один вариант
не отмечен. Можно задать время (`duration`) — потом вернётся прежняя (временная смена не сохраняется: при перезаходе — прежняя),
и перезарядку: `Keep` (у каждой своя), `Carry` (новая получает остаток старой), `Reset` (сразу готова). Хук
`Hooks.Spells.OnSlotSpellChanged` срабатывает и на выбор игрока, и на смену плагином, и на возврат. В правилах: действие
`slot.set` (слот, способность, режим, время, перезарядка), условие `slot.is`, триггер `slot.changed`. Для проверки в игре —
GM-команды `.slot list` и `.slot <слот> <способность> [any] [секунды]`, например `.slot Q CLEAVE` или `.slot Q RENDINGSTRIKE any 20`.

## Правила без кода

Правило — это «**Когда** → **Если** → **Сделать** → **С кем**» без программирования: например «моб X умер → с шансом
10 % → выдать предмет Y → убийце», «ночью в чёрных зонах → слава ×1.5», «команда `.home` → телепорт, раз в 10 минут».
Правила работают только на сервере (клиент не меняется), поэтому **сохранение сразу применяет их на запущенном сервере** —
без «Сгенерировать», установки и перезапуска. Справочник на английском: `server/plugins/RULES.md`.

Где лежат: `mods/<пак>/rules/<id>.json`, по файлу на правило. Работают правила паков из `Mods:Packs` (как дропы и плагины
пака). Сервер грузит их при старте одним встроенным плагином `rules` (та же защита, что у C#-плагинов);
`.rules reload` (Admin) перечитывает их без перезапуска, `.rules` показывает, что работает и сколько раз сработало,
`.rules problems` — почему правило не загрузилось.

**В Студии:** в левой панели пака раздел «Правила» (+ — новое правило), или «+ Новое… → Правило — из шаблона…».
Галерея шаблонов: +50 % славы ночью в чёрных зонах; босс даёт предмет всей группе; зелья лечат на 20 % больше у хилеров
(с посохом света); объявление об убийстве мирового босса; ежедневная награда за вход; команда `.home` с перезарядкой;
счётчик убийств с наградой каждые 100 (два правила, связанные цепочкой); запрет садиться на маунта в бою; вечернее событие.
Форма правила:
- **Когда** — триггер и фильтр по id (заклинание, бафф, предмет, маунт, моб — через обычные пикеры каталога; `*` — любой
  текст, список через запятую — любой из них) и параметры триггера (процент здоровья, команда, интервал таймера…);
- **Если** — условия (все / любое), у каждого «НЕ» и «у кого» (сам, убийца, жертва, кастер, цель, моб); добавить, удалить,
  переставить, скопировать;
- **Сделать** — действия по порядку, у каждого своя цель или цель правила по умолчанию;
- **С кем** — цель по умолчанию: сам, убийца, жертва, кастер, цель, моб, группа, все в кластере, игроки в радиусе, все онлайн;
- **Ограничения** — перезарядка (на игрока или общая; от минуты и больше переживает перезапуск), максимум срабатываний
  (на игрока или всего), не больше N срабатываний в секунду, сообщение при невыполненных условиях (для команд).
Проблемы показываются у полей сразу, а правило с блокером на сервер не грузится (остальные работают).
«Проверка (симуляция)» справа: выбрать игрока онлайн — условия проверяются на нём сейчас, действия только описываются
(ничего не выдаётся). «Править JSON…» — для тех, кому так быстрее.

**Триггеры:** вход/выход игрока, вход/выход из кластера, нокдаун, смерть, подъём, вход/выход из боя, здоровье ниже %,
сообщение в чате, своя команда чата, вступление/выход из группы, выполненная цель; смерть и появление моба, выпавший лут,
любой удар; использование, крафт, надевание/снятие, поломка предмета, сбор ресурса/рыбалка; заклинание: проверка (можно
запретить), каст, попадание (можно отменить эффект), урон/лечение (можно изменить), прерывание; бафф: проверка (можно
запретить), наложен, закончился, тик; маунт: попытка сесть (можно запретить), сел, спешился, удар по маунту; формулы:
кулдаун, время каста, энергия, лечение, слава за убийство, серебро с моба, угроза; таймер каждые N секунд, каждый день в
ЧЧ:ММ; «цепочка» (вызов из другого правила).

**Условия:** шанс %, уровень аккаунта, предмет в сумке, надетый предмет, бафф, здоровье %, в бою, игрок/моб, серебро,
размер группы, кластер, цвет зоны (safe, yellow, orange, red, black), время суток, день недели, тир / категория моба,
мировой босс, переменная/счётчик (на игрока или общая, хранится между перезапусками), число события (урон, слава…),
деталь события (лечение, первый вход, прерван…), текст чата / аргументы команды.

**Действия:** сообщение (игроку, ошибкой, объявление всем, в зону; подстановки `{player}`, `{mob}`, `{amount}`,
`{var:имя}`…), выдать/забрать предмет, серебро, славу, наложить/снять бафф, урон/лечение (числом или % здоровья),
телепорт, отбросить/притянуть/рывок, призвать мобов (со временем жизни), мировой босс, мировое событие, изменить
переменную, добавить в лут, изменить число события (×, +, =), запретить, отменить стандартный эффект, применить
заклинание из spells.xml, задать/сбросить кулдаун, запустить цепочку (сразу или через N секунд), записать в лог.

Безопасность: правило, упавшее `Plugins:MaxErrors` раз, отключается (остальные работают); лишние срабатывания сверх
лимита в секунду пропускаются; при загрузке каждое правило проверяется (неизвестные триггеры/условия/действия, пропущенные
параметры, несуществующие предметы, заклинания и мобы, недоступные цели, «изменить число» у события без числа, занятая
команда) — с понятным сообщением, а сломанное правило не грузится.
